## 問題の形（自動・手書き共通）

`ReadingQ = { no, kind, sentenceId, span: [開始, 終了], spanText, tokenIds, prompt, choices, answerIndex, explain, lemma?, qid?, target?, grammarRefId? }`。
傍線は**文字範囲**（その文の `originalText` の中の位置。終了は含まない）で持ち、文をまたがない。自動問題はトークンの `start`／`end` から範囲を出す（語に付いた「、」などの句読点は外す）。`tokenIds` は記録用。

## 第1段：自動問題の作り方（捏造しない）

1. **語の意味**（`vocab`）：単語帳（330）に紐づく語。紐づけは読解ページと同じ `resolveVocabKey`（助詞・助動詞は対象外）。
   - この箇所の意味 = 決め手（`public/analysis/<id>.json` の `decider.meaning`）→ 品詞分解の意味（`grammarTag.meaning`。「尊敬語」などの類別だけのものは使わない）。それを `cardSenses`（WordCard と同じ）で単語帳の意味に照らし、当たらない語は出さない。
   - 理由が「単語帳の意味（…）とは別に」で始まる語は出さない。
   - 誤りの選択肢：同じ見出しのほかの意味 → 同じ品詞のほかの語の意味。同義の重なりは `canUseAsDistractor`（`senseEquivalence.ts`）で除き、表示の重なりも除く。表示は辞書形（`senseLabel`＋補助動詞は「補動」）。誤りが2つ未満なら出さない。
   - 傍線は**語だけ**。
2. **文法的意味**（`grammar`）：助動詞。意味 = 決め手の `meaning` → 品詞分解の意味（`grammarMeaningLabel` で略記を戻し、現推→現在推量 などをそろえる）。
   - どの助動詞か = 本文の形と意味から `AUX_TABLE` で決める（「に」＋完了＝ぬ、「に」＋断定＝なり、「ぬ」＋打消＝ず など）。表に無い組は出さない。
   - 誤りの選択肢：その助動詞が取りうる意味（`AUX_TABLE`。出典＝文法道場の単元 `public/grammar/jodoshi-*.json` の意味の表）→ 同じ形のほかの助動詞の意味 → 一般の意味（過去・完了・推量…）。4択。
   - 傍線は**文節**（前の用言＝複合した用言は2語まで、無ければ前の体言など1語＋助動詞の連なり＋尊敬の補助動詞「たまふ」）。連なりの中の1語（意味の数が多い語）を「傍線部②「にけり」の中の助動詞「けり」」のように指して問う。同じ形が2つあれば「2つ目の」と言う。
   - **助動詞が2つ以上続く箇所を優先**し、次に意味が2つ以上ありうる語。
- 1教材あたり最大8問。語の意味と文法を半々（足りない方を他方で埋める）。文法は優先順に、語の意味は文法の傍線と重ならない語から本文全体に散らして選び、本文の前から順に番号を振る。同じ語（見出し・助動詞）は1回。並びは決定的（FNV ハッシュで並べ替え）。
- 語の意味の正解は決め手か意味ラベルが無いと決められないので、単語の理由がまだ無い教材（非公開の多く）は文法だけになる。

## 手書きの問題ファイル

`public/reading-tests/<textId>.json` があれば自動問題の代わりに使う（無い・読めない・有効な問題が0なら自動）。

```json
{ "textId": "...", "title": "...", "lead": "出典・背景の1〜2行",
  "questions": [ { "no": 1, "kind": "vocab|grammar|subject|kakari|reading", "sentenceId": "s3",
    "span": [開始, 終了], "spanText": "傍線部の文字列（検査用）", "prompt": "問い文",
    "choices": ["..", ".."], "answerIndex": 1, "explain": "解説（1〜3文）" } ] }
```

- `span` はその文の `originalText` の中の文字位置（終了は含まない）。`spanText` が本文の該当範囲と一致しない問題、文・範囲・kind・選択肢（2つ以上・重複なし）・`answerIndex` が正しくない問題は読み込み時に捨てて `console.warn`。
- 番号は捨てた分を詰めて振り直す（問い文の先頭の「傍線部①」も合わせる）。`explain` は答え合わせの吹き出しに出す。
- 傍線の長さは語だけ・句・一文が混ざるようにする（自動問題は語＝語の意味、文節＝文法）。
- 火鼠の皮衣（5954a8d9eb）・龍の首の玉（cd8147e868）は別の担当が書く予定。

## 第2段の予定

kokugo-vault の教材 MD に、主語（`subject`）・係り先（`kakari`）・内容（`reading`）の選択式問題を書き起こし、上の手書きの形で `public/reading-tests/` に出す（源流は vault、配信はアプリ）。自動では作らない（正解が品詞分解のデータから決まらないため）。書き起こしでは、傍線を句・一文にも引き、誤りの選択肢は本文の別の人物・別の箇所から取る。
