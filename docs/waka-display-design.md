## 2. 画面構成

### 案1（推奨）横書き・歌ごとのかたまり

`mock-390.png` の上半分。歌集名 → 歌のかたまり（詞書・歌・歌人名・訳）の繰り返し。

```
古今和歌集                                  ← 小さな見出し＋罫
寛平の御時后宮の歌合の歌 (春)              ← 詞書 14px 薄墨。部立は小さな札。割れた詞書は1つにつなぐ
│ 春の野に  若菜つまむと  来しものを        ← 歌 19px、左に罫。句の間に空き
│   散りかふ花に  道はまどひぬ               ← 下の句は1字下げ（三句切れが見える）
                              紀貫之       ← 歌人名 13px 右寄せ
[歌意] 春の野に若菜を摘もうと…    (逐語訳)  ← 訳は「歌意」を既定、逐語訳は切替
```

- 語の色分け（用言＝青・助動詞＝橙・助詞＝緑）と浮かぶ解説カードは今のまま使える（横書き前提の操作を壊さない）
- 上の句／下の句で行を分けるので、スマホでも句の途中で折り返さない。字余りの句も句単位で折り返す
- 長歌は「5・7」を1行に、末尾に「反歌」の見出し、反歌は短歌と同じ形
- 近世の句は1行（5・7・5）、作者は句のかたまりごと（芭蕉4句・蕪村4句・一茶4句）にまとめて右寄せ
- 歌謡（今様・小歌）は今の行をそのまま行として並べ、「梁塵秘抄」「閑吟集」の見出しを足す
- 訳：歌は「歌意」（modernTranslation）を既定にし、逐語訳（chikugo）は札で切り替える。18区切りを点線で並べた逐語訳は歌では読みにくい。詞書の訳は詞書のかたまりに1つ
- 読解(5)・識別(6)のレイヤーもこの枠組みの中で今どおり動く（アノテーションは歌の行に付く）

### 案2 縦書きカード（教科書と同じ形）

`mock-390.png` の下。1首を縦書きの札にする。教科書と同じ見た目で、句切れを入れなくても読める。
欠点：浮かぶ解説カード・なぞり操作が横書き前提（`wordCardLayout` の上下判定）で作り直しになる。1首あたり高さ560px前後を使い、49文の王朝の歌では縦に長い。縦書きは読解テストと品詞分解PDFにすでにあるので、教材画面は案1にして縦書きはそちらに任せる。

### 触らないもの

品詞分解PDF（縦書き。スペースの右寄せが教科書どおりに見える）、読解テスト（縦書き・閲覧のみ）、解説ページ。

## 3. データの形

### 3-a. 画面側の推定だけ（データ不変）

`src/lib/kobun/wakaLayout.ts`（下書き済み・未接続）：スペース連続のトークンで「頭／歌人名」に分け、1トークンの「〜集」を歌集名、歌人名の文の直前に続く句読点つき・短い文を詞書の切れ端として結合、句の間に全角スペースのある行を長歌として束ねる。
できること＝歌人名の右寄せ・詞書の結合・見出し・空の訳帯を消す。できないこと＝句の切れ目（上の句／下の句）、近世の句の作者のまとめ、反歌の見出し、歌謡の見出し。推定なので例外が出たら画面で崩れる。

### 3-b. 和歌の構成ファイルを1層足す（推奨）

`public/waka/<textId>.json`。reading・analysis・chikugo・reading-tests と同じ「文IDを指す並行層」の作法で、texts-v3 と文番号は変えない。初版は 3-a の推定で生成し、句の切れ目と作者だけ手で足して確かめる。

```json
{
  "textId": "f0740d6350",
  "blocks": [
    { "type": "collection", "title": "古今和歌集", "sentenceIds": ["s1"] },
    { "type": "poem", "form": "tanka", "category": "春",
      "kotobagaki": ["s2"], "author": "紀貫之", "authorSentenceId": "s2",
      "lines": [ { "sentenceId": "s3", "ku": [4, 11, 15, 22] } ] },
    { "type": "poem", "form": "tanka", "category": "秋",
      "kotobagaki": ["s6", "s7"], "author": "素性", "authorSentenceId": "s7",
      "lines": [ { "sentenceId": "s8", "ku": [5, 11, 15, 19] } ] },
    { "type": "poem", "form": "choka", "kotobagaki": ["s3"], "author": "柿本人麻呂", "authorSentenceId": "s3",
      "lines": [ { "sentenceId": "s4" }, { "sentenceId": "s5" } ],
      "hanka": [ { "sentenceId": "s11", "ku": [5, 10, 15, 20] }, { "sentenceId": "s12", "ku": [5, 11, 15, 20] } ] },
    { "type": "poem", "form": "hokku", "author": "松尾芭蕉", "authorSentenceId": "s1",
      "lines": [ { "sentenceId": "s1", "ku": [5, 12] }, { "sentenceId": "s2", "ku": [3, 9] } ] },
    { "type": "song", "title": "梁塵秘抄", "lines": [ { "sentenceId": "s46" }, { "sentenceId": "s47" } ] }
  ]
}
```

- `ku` は originalText の文字位置（切る位置。短歌4つ・発句2つ・長歌の行は全角スペースで切るので不要）。字余り・字足らずでも「句の境界」を書くだけなので迷わない
- `kotobagaki` に複数の文IDを書けば、割れた詞書が1つにつながる。`authorSentenceId` の文のスペース以降が歌人名（画面はそこを外して描く）
- 作者は「かたまり」に付くので、近世の句の2句目以降にも作者が付く
- 読み仮名を足さずに済む（読み仮名を入れるなら token.furigana で全教材に関わる別の仕事）

検査（`scripts/check-texts.mjs` に T17 として追加）：全文が1回ずつどこかの block に現れる／`ku` がトークンの境界に乗る／短歌は `ku` 4つ・発句は2つ／`authorSentenceId` の文にスペース連続のトークンがある／`kotobagaki` の文の連結（スペース除く）が詞書として途切れていない（先頭が「」る に」などで始まらない）。

画面：TextReader は `/waka/<id>.json` があれば block で描き、無ければ今どおり（スペース連続の右寄せだけは全教材共通で直す）。

### 3-c. texts-v3 を切り直す（今回は見送り）

詞書を1文に・歌人名を文の属性に・歌を1文にする本来の形。文番号が analysis・reading・chikugo・reading-tests・用例バンク（sentenceId/tokenId）・corpus-additions・vault の「第N文」まで連動するため、2026-11-06 に歌を足したときと同じ全層の付け替えになる。見た目は 3-b で同じになるので、今回はやらない。将来 vault の和歌の本文の書式（詞書／歌／作者の表）を決め直すときに一緒にやる。
